K　HMM 知識核心・2026-11-12

K 核心系統架構

原始資料經本地 LLM 或 API 進入 K，通過驗證與人工確認後成為演變序列，再依場域訓練 HMM。規劃中的知識萃取與 AoV 生成協助，都建立在已完成的模型版本與推論之上。

整體資料流

LLM 轉換的狀態

LLM 負責：理解內容

  • 從原始資料找出初始流程與每次修改
  • 把各種寫法的工序對應到活動類型
  • 區分原因是原文抄錄還是自己推論
  • 把不確定的地方寫進 notes

程式負責：確定性的工作

  • 產生序列、事件、版本的識別碼
  • 由前後完整版本計算差異、推定修改類型
  • 檢查 DAG、順序與版本鏈
  • 核對 human 原因能否在原文逐字找到
