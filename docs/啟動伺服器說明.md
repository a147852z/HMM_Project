# 啟動伺服器說明

本專案有兩套系統，各有一組後端與前端：

| 系統 | 位置 | 後端埠 | 前端埠 | 用途 |
|---|---|---|---|---|
| K：HMM 知識核心 | `k_core/` | 8900 | 5174 | AoV 演變序列、HMM 訓練、模型研究、生成協助、LLM 轉換與審核（目前主要使用） |
| ERP 模擬平台（舊平台） | `erp_hmm_simulator/` | 8800 | 5173 | ERP 使用者行為模擬與 HMM 預測 |

兩套系統的埠號不同，可以同時啟動。以下指令都在 PowerShell 執行，路徑以專案根目錄 `E:\程式碼\ERP_HMM_Project` 為起點。

## 事前準備

- Python 3.11 以上
- Node.js 20 以上
- （選用）本地 LLM 伺服器：只有使用「轉換設定／轉換與審核」時才需要，見最後一節

## 一、K 知識核心（k_core）

### 1. 第一次安裝（只需做一次）

```powershell
cd k_core\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"

cd ..\frontend
npm install
```

`.venv` 已經存在時可以跳過建立虛擬環境，直接啟用它。

### 2. 啟動後端（第一個終端機視窗）

```powershell
cd k_core\backend
.\.venv\Scripts\Activate.ps1
python -m uvicorn kcore.main:app --reload --port 8900
```

不想啟用虛擬環境時，也可以直接呼叫虛擬環境裡的 Python：

```powershell
cd k_core\backend
.\.venv\Scripts\python.exe -m uvicorn kcore.main:app --reload --port 8900
```

看到 `Uvicorn running on http://127.0.0.1:8900` 就表示啟動完成。確認方式：

- 健康檢查：<http://localhost:8900/health>
- API 測試介面：<http://localhost:8900/docs>

### 3. 啟動前端（第二個終端機視窗）

後端要先啟動，再執行：

```powershell
cd k_core\frontend
npm run dev
```

用瀏覽器開啟 <http://localhost:5174>。前端會把 `/api` 與 `/health` 的要求轉送到 8900 埠的後端。

常用網址：

- `http://localhost:5174/#case/CVFLOW`：直接開啟 CVFLOW 案例的模型研究頁面
- `http://localhost:5174/#case/CVFLOW/assist`：直接開啟生成協助測試
- `http://localhost:5174/#review/<轉換代號>`：直接開啟某次轉換的審核畫面

### 4. 資料庫

- 預設使用 `k_core\backend\kcore.db`（SQLite）。**必須在 `k_core\backend` 目錄下啟動後端**，因為預設路徑 `sqlite:///./kcore.db` 是相對於目前目錄；在其他目錄啟動會建立一個新的空資料庫。
- 要改用其他資料庫時，啟動前設定環境變數：

  ```powershell
  $env:KCORE_DATABASE_URL = "sqlite:///./kcore.backup-20261118.db"
  python -m uvicorn kcore.main:app --reload --port 8900
  ```

- 執行實驗或匯入腳本（例如 `scripts\cvflow_ingest_update.py`）前，建議先複製一份 `kcore.db` 備份。

### 5. 改用其他埠

8900 埠被占用時，可以把後端開在其他埠，前端啟動前用 `KCORE_API_URL` 指定後端位置：

```powershell
# 後端
python -m uvicorn kcore.main:app --reload --port 8901

# 前端（另一個視窗）
$env:KCORE_API_URL = "http://localhost:8901"
npm run dev
```

### 6. 建立前端正式版本（選用）

```powershell
cd k_core\frontend
npm run build      # 先做型別檢查，再輸出到 dist\
npm run preview    # 在本機預覽正式版本
```

## 三、本地 LLM 伺服器（選用）

K 的「轉換設定（提示詞）」與「轉換與審核」會呼叫 OpenAI 相容的 API（`GET {網址}/models`、`POST {網址}/chat/completions`）。預設網址是 `http://localhost:1234/v1`（LM Studio 的預設埠）。

1. 啟動 LM Studio（或其他 OpenAI 相容伺服器），載入要用的模型並開啟本機伺服器。
2. 在 K 的「轉換設定（提示詞）」分頁填寫網址與模型名稱，按「測試連線」確認。
3. 伺服器需要金鑰時，在設定裡填寫存放金鑰的**環境變數名稱**，並在啟動 K 後端前設定該環境變數；金鑰本身不會存進資料庫。

不使用轉換功能時，不需要啟動 LLM 伺服器，其他頁面都能正常使用。

## 四、常見問題

| 狀況 | 原因與處理 |
|---|---|
| 畫面顯示「找不到這項功能的 API」 | 後端是舊版程式。更新程式後請重新啟動後端（`--reload` 會在 Python 檔案變更時自動重新載入，但切換分支、安裝套件或改環境變數後仍建議手動重啟）。 |
| 前端打得開，但資料都載入失敗 | 後端沒有啟動，或不在 8900 埠。先開 <http://localhost:8900/health> 確認；後端在其他埠時設定 `KCORE_API_URL`。 |
| 案例清單是空的 | 後端不是在 `k_core\backend` 目錄下啟動，連到了新建立的空資料庫。回到正確目錄重新啟動，或用 `KCORE_DATABASE_URL` 指定完整路徑。 |
| `Address already in use` / 埠被占用 | 已經有一個後端在跑。用 `Get-NetTCPConnection -LocalPort 8900` 找出程序後關閉，或改用其他埠（見第一節第 5 點）。 |
| `.\.venv\Scripts\Activate.ps1` 無法執行（執行原則限制） | 執行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，或不啟用虛擬環境，直接用 `.\.venv\Scripts\python.exe` 執行。 |
| 轉換時顯示無法連線到 LLM | LM Studio 沒有開啟本機伺服器，或網址、模型名稱不符。用「測試連線」檢查。 |
